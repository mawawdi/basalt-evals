# Authored gate controls

The working implementation is an evaluator-side control, outside the public
builder seed. It is not a builder treatment, model reference, expert label or
visual-quality verdict. It handles a real `E` input, server-side distance and
identity checks, the pairing and open deadlines, replication and disconnect
cleanup. The deliberately broken `trusts-distant-request` variant is generated
from the same source by removing only the server's proximity check. The fixed
`forged-and-distant` scenario must reject that variant. A second broken variant
opens for one player and must fail `first-cannot-open`. The working control
must pass every required deterministic criterion.

These sources remain regression authorities. The standalone launcher is retired.
New control captures use the shared operator after source registration against a
current compiled eval, with one quote, journal and serialized native adapter.
Historical receipts remain read-only archives and cannot execute old evaluators.

The post-ready-barrier runs on 2026-09-21 are retained locally as
`gate-control-working-barrier-1790019760` (20/20 required criteria),
`gate-control-distant-barrier-1790020260` (18/20), and
`gate-control-single-barrier-1790020600` (14/20). Their signed native receipts
and `control.json` files distinguish complete execution from a rejected mechanic.
